# Техническое задание  
## Telegram-бот для автоматической генерации рефератов с использованием локальной нейросети

**Версия:** 2.0  
**Дата обновления:** 25.07.2026  


### 1. Общее описание проекта

Необходимо разработать Telegram-бота, который по запросу пользователя автоматически генерирует реферат на заданную тему и отправляет готовый файл в формате `.docx` (Microsoft Word).

Генерация текста выполняется локальной языковой моделью (Gemma, DeepSeek, Qwen или аналогичные). Для снижения количества галлюцинаций модель в обязательном порядке получает дополнительный контекст из интернета — результаты поиска DuckDuckGo и материалы русскоязычной Википедии.

Важной особенностью системы является поддержка **нескольких шаблонов оформления и структуры** реферата. Это необходимо из-за того, что разные преподаватели предъявляют разные требования к оформлению и структуре работы. Пользователь должен иметь возможность выбрать нужный шаблон перед генерацией.

Система должна работать полностью автоматически после запуска.


### 2. Цели проекта

- Автоматическая генерация структурированных рефератов по теме пользователя.
- Использование исключительно локальной нейросети (без платных внешних API).
- Снижение галлюцинаций за счёт поиска информации в DuckDuckGo и Википедии.
- Поддержка нескольких шаблонов структуры и оформления реферата под требования разных преподавателей.
- Выдача результата в виде корректно оформленного файла `.docx`.
- Полная автоматизация процесса после запуска системы.


### 3. Основные функции системы

1. Приём темы реферата от пользователя.
2. Возможность указания краткого плана или дополнительных требований.
3. Выбор шаблона оформления и структуры реферата.
4. Автоматический поиск информации:
   - DuckDuckGo
   - Русскоязычная Википедия
5. Формирование промпта с учётом выбранного шаблона и найденного контекста.
6. Генерация текста реферата локальной нейросетью.
7. Создание Word-документа на основе выбранного шаблона оформления.
8. Отправка готового `.docx` файла пользователю.
9. Информирование пользователя о текущем статусе выполнения запроса.
10. Автоматическое удаление временных файлов после отправки.


### 4. Пользовательский сценарий (основной)

1. Пользователь запускает бота командой `/start`.
2. Бот показывает краткую инструкцию.
3. Пользователь выбирает шаблон оформления (кнопками или командой).
4. Пользователь отправляет тему реферата.
5. (Опционально) Пользователь может отправить краткий план или особые требования.
6. Бот последовательно сообщает статусы:
   - «Ищу информацию…»
   - «Генерирую реферат…»
   - «Формирую документ…»
7. Бот отправляет готовый файл `.docx` с понятным именем.
8. Временные файлы удаляются с сервера.


### 5. Архитектура системы

Система состоит из следующих основных компонентов:

#### 5.1. Telegram-бот
- Принимает сообщения и команды от пользователей.
- Позволяет выбор шаблона.
- Управляет диалогом.
- Отображает статусы выполнения.
- Отправляет готовый файл пользователю.

#### 5.2. Оркестратор (основная бизнес-логика)
- Получает тему, план и выбранный шаблон.
- Выполняет поиск в DuckDuckGo.
- Получает данные из Википедии.
- Формирует итоговый промпт в соответствии с выбранным шаблоном.
- Отправляет запрос на ИИ-сервер.
- Получает сгенерированный текст.
- Передаёт текст и выбранный шаблон в модуль генерации Word.
- Возвращает готовый файл боту.

#### 5.3. ИИ-сервер
- Локальная языковая модель.
- Предоставляет HTTP API для генерации текста.
- Принимает промпт и возвращает готовый текст.

#### 5.4. Модуль генерации Word-документов
- Использует заранее подготовленные `.docx` шаблоны.
- Вставляет сгенерированный текст в соответствующий шаблон.
- Применяет нужное оформление (шрифты, стили заголовков, поля и т.д.).

#### 5.5. Хранилище шаблонов
- Набор текстовых промптов под разные структуры рефератов.
- Набор `.docx` файлов-шаблонов под разное оформление.

### 8. Детальные требования к компонентам

### 8.1. Telegram-бот

- Команда `/start` — приветствие и краткая инструкция.
- Возможность выбора шаблона с помощью кнопок (InlineKeyboard).
- Приём темы реферата.
- Возможность приёма дополнительного плана/требований.
- Отображение промежуточных статусов генерации.
- Отправка готового файла с понятным именем (например: `Реферат_Причины_Первой_мировой_войны.docx`).
- Корректная обработка ошибок с понятными сообщениями пользователю.
- Рекомендуется ограничение: не более одного активного запроса от пользователя одновременно.

### 8.2. Система шаблонов

Система должна поддерживать несколько шаблонов. Каждый шаблон состоит из двух частей:

1. **Промпт-шаблон** — определяет структуру и стиль генерируемого текста.
2. **Word-шаблон** — определяет внешнее оформление документа.

Примеры шаблонов (список может расширяться):
- Стандартный школьный
- Вузовский с содержанием
- По требованиям конкретного преподавателя (Иванова, Петров и т.д.)

Пользователь обязан выбрать шаблон перед генерацией.

Хранение шаблонов организуется через конфигурационный словарь/файл, например:

```python
TEMPLATES = {
    «standard»: {
        «name»: «Стандартный школьный»,
        «prompt_file»: «prompts/standard.txt»,
        «docx_template»: «templates/standard.docx»
    },
    «ivanova»: {
        «name»: «Преподаватель Иванова»,
        «prompt_file»: «prompts/ivanova.txt»,
        «docx_template»: «templates/ivanova.docx»
    }
}
```

### 8.3. Поиск информации

**DuckDuckGo:**
- Выполняется 1–3 поисковых запроса по теме.
- Используются топ-5–8 результатов (заголовок, сниппет, ссылка).

**Википедия:**
- Используется русскоязычная версия.
- Берутся краткое содержание статьи и 2–4 наиболее релевантных раздела.
- Объём передаваемого текста ограничивается, чтобы не превышать контекстное окно модели.

Поиск выполняется автоматически после получения темы и выбора шаблона.

### 8.4. Формирование промпта

Промпт должен включать:
- Роль и инструкции для модели.
- Выбранный шаблон структуры.
- Тему реферата.
- План пользователя (если указан).
- Контекст, полученный из DuckDuckGo и Википедии.
- Требования не выдумывать факты и источники.
- Чёткое указание структуры (введение, основная часть с подзаголовками, заключение, список литературы).

### 8.5. ИИ-сервер

- Предоставляет HTTP-эндпоинт (рекомендуется `POST /generate`).
- Принимает готовый промпт.
- Возвращает сгенерированный текст.
- Модель должна качественно работать с русским языком.
- Рекомендуемые модели: Gemma-2-9B, Qwen2.5-7B/14B, DeepSeek-R1-Distill 8B/14B (в зависимости от доступного железа).

### 8.6. Генерация Word-документа

- Используется выбранный `.docx` шаблон.
- В шаблон вставляется сгенерированный текст с сохранением структуры.
- Документ должен иметь корректное оформление в соответствии с шаблоном (шрифты, поля, стили заголовков, интервалы и т.д.).
- Имя файла формируется на основе темы реферата.


### 9. Нефункциональные требования

- Полная автоматизация работы после запуска.
- Время генерации одного реферата — ориентировочно до 2–4 минут (зависит от железа и модели).
- Все временные файлы должны удаляться после отправки пользователю.
- Корректная обработка ошибок сети, таймаутов, пустых результатов поиска и сбоев модели.
- Код должен быть модульным и читаемым.
- Система должна позволять легко добавлять новые шаблоны без изменения основной логики.


### 10. Ограничения и важные замечания

- Локальные модели имеют ограниченный контекст — нельзя передавать слишком большие объёмы текста из Википедии.
- Качество итогового реферата напрямую зависит от качества промпта, выбранного шаблона и найденного контекста.
- Бот рекомендуется позиционировать как помощника для подготовки структуры и черновика, а не как инструмент для сдачи готовых работ.
- Необходимо предусмотреть базовую защиту от злоупотреблений (частые запросы от одного пользователя).


### 11. Этапы разработки

1. Установка и настройка локальной модели (Ollama + выбранная модель).
2. Создание HTTP API для генерации текста.
3. Разработка минимального Telegram-бота (приём темы → возврат текста).
4. Реализация системы выбора шаблонов.
5. Подключение поиска DuckDuckGo и Википедии.
6. Разработка и подключение промпт-шаблонов.
7. Создание и подключение Word-шаблонов.
8. Интеграция генерации `.docx`.
9. Добавление статусных сообщений, обработки ошибок и очистки временных файлов.
10. Тестирование и полировка.


### 12. Критерии готовности (Definition of Done)

Система считается готовой к использованию, когда выполняются следующие условия:

- Пользователь может выбрать шаблон, отправить тему и получить готовый `.docx` файл.
- Документ соответствует выбранному шаблону по структуре и оформлению.
- При генерации используется информация из DuckDuckGo и/или Википедии.
- Бот корректно отображает статусы выполнения.
- Ошибки обрабатываются и сообщаются пользователю понятным языком.
- Временные файлы не накапливаются на сервере.
- Добавление нового шаблона возможно без переписывания основной логики.


### 13. Возможности дальнейшего развития (не входят в обязательный объём первой версии)

- Указание желаемого объёма реферата (количество страниц).
- Возможность доработки уже сгенерированного реферата («перепиши введение», «добавь раздел» и т.д.).
- Автоматическая генерация титульного листа.
- Экспорт в PDF.
- Полноценная очередь задач для одновременной обработки нескольких пользователей.
- Сохранение истории запросов пользователя.
- Административная панель для управления шаблонами.
